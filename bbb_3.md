# BBB(3) = 55

The **Beeping Busy Beaver** value for 3 states and 2 symbols (Shawn Ligocki; definition on the
[bbchallenge wiki](https://wiki.bbchallenge.org/wiki/Beeping_Busy_Beaver)) is 55.  The champion
is `1LB0RB_1RA0LC_1RC1RA` (and its three copies under mirroring and swapping B, C): from step 56
on it stays in state C, moving left on a blank tape; state B is visited for the last time at step
55 (state A at step 54).

## Definition and conventions

A machine starts in state A on a blank tape.  For a beep state `q`, the machine beeps at every
step taken in `q` (the halting step included).  If it beeps finitely often, its value for `q` is
the step of its last beep, counting steps from 1.  BBB(3) is the largest such value over all
3-state machines and states.  Halting machines are included: the halting state beeps last at the
halting step, so BBB(3) ≥ BB(3) = 21.  In Lean: `Bbbb.LastBeep`, `Bbbb.IsBBB`
(`lean/Bbbb/Bbb/Defs.lean`).

The value of a *machine* in the table below and in the data file is the largest last beep over
its three states.  A state that is never visited counts 0, and `∞` means every state is visited
infinitely often.  BBB(3) is the largest finite value.

## Status of the Lean proof

`lean/Bbbb/Bbb/Main3.lean`, core Lean 4.15, kernel-checked (`decide +kernel`, no `native_decide`):

```lean
theorem champB3_last : LastBeep champB3 1 55     -- the champion, beep state B: proven
theorem bbb3 (hh : HoldsB3Covered) : IsBBB 2 55  -- BBB(3) = 55, given the holdouts
```

`lake env lean Check.lean` reports only `propext`, `Classical.choice`, `Quot.sound`.  The
hypothesis `HoldsB3Covered` says that the 28 holdout leaves `holdsB3` (7 machines up to
mirroring and swapping B, C; 220 full machines) have no finite last beep above 55.  Simulation
for 200 000 steps shows that all of them visit every state infinitely often:

| Holdout (up to symmetry) | Behaviour |
|---|---|
| `0LB0RA_1LC---_1RA1LB` | binary counter (digits `10` / `00`) |
| `0LB0RA_1RA1LC_1LB---` | binary counter |
| `1LB---_1RC1LA_0LA0RC` | binary counter |
| `1LB1RC_0RA0LB_1RA---` | binary counter |
| `1LB1RC_0RC0LB_1RA1LC` | binary counter |
| `1LB0LB_1RB1RC_1LA0RA` | bouncer over a growing block of `1`s |
| `1LB0RB_1RA0LC_1LC0LA` | bouncer over a growing block of `10`s |

These need exact counting (a bouncer or counter theorem), which the abstraction below does not do.

## Method

The machines are covered by the tree of partial machines of the BBBB(3) proof (`Tree.lean`,
`tools/bbbb3/tree3.pkl`).  A node runs until it reaches an undefined transition and branches on
its 12 choices.  It also covers the halting choice, which halts after `t + 1 ≤ 21` steps.  The
leaves are:

* **74 196 translated cyclers** (`Bbb/Leaf.lean`, `checkLeafB`): the transitions are eventually
  periodic.  States in the period are visited forever.  Every other state must last occur in the
  preperiod by step 55.
* **3 712 recurrence certificates** (`Bbb/Tail.lean`, `Bbb/Abs.lean`, `Bbb/Rec.lean`), for the
  bouncers and counters that can be handled without exact counting.
  * An abstract node is a window of radius `R` around the head plus a kind for each tape tail:
    blank, nonblank, any, or `a[i:] a^m w` / `w[j:]` for small words `a`, `w`.
  * The abstract step `asucc` is proven sound.  The certificate is a set of nodes closed under
    `asucc` and reached after a concrete prefix of `t0` steps, so the machine never halts.
  * For each state `q` there is a rank per node: a list of constants and tail measures (the
    stripped tail lengths).  It decreases lexicographically along every edge between nodes not
    in `q`.
  * There is no infinite lexicographic descent (`no_descent`), so `q` is visited infinitely
    often.  States that occur in no node are visited only in the prefix.
  * Generated by `tools/bbb3/absgraph.py`.  The ranks come from repeated strongly connected
    component decomposition.
* **28 holdouts** (above).

`tools/bbb3/gen_bbb3.py` writes `lean/Bbbb/Bbb/Certs/` (308 chunk files, 6764 forests).  A clean
build of these takes about 9 minutes on 24 cores, about 1 GB per Lean process.

## Data file

`bbb_3.txt.gz` lists all 13⁶ = 4 826 809 machines, one per line as `[value] [machine]`, sorted by
value (descending), with `inf` for ∞.  Each transition is one of the 12 proper choices or halting
(`---`).  What a halting transition would write or where it would move does not matter, so it is
listed once.  Counting those variants separately gives a larger number of machines with
identical values.  Values of the 220 machines extending the holdouts come from simulation.
